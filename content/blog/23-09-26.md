Local call versus remote call
A local call such as:
result := chargeCard(orderID, amount)
runs inside the same process. The caller and function normally share memory, a call stack, and one failure boundary.
An RPC only looks like a function call:

Client process                                      Server process

ChargeCard(...)
     |
serialize arguments
     |
write bytes to socket
     |
client OS ───── network ───── server OS
                                  |
                           read bytes
                                  |
                           deserialize
                                  |
                           run handler
                                  |
                           modify database
                                  |
                           serialize response
                                  |
client OS <───── network ───── server OS
     |
deserialize response
     |
return result

What TCP actually guarantees
TCP provides an ordered, reliable byte stream while the connection is functioning:
- It retransmits lost packets.
- It removes duplicate packets.
- It presents bytes to the receiving application in order.
- It detects some connection failures.
TCP does not guarantee that:
- delivery will eventually succeed;
- the server application read the bytes;
- the server completed the operation;
- the database committed the operation;
- the response reached the client;
- a failed connection reveals whether the operation succeeded;
- a retry on a new connection will not repeat the operation.
